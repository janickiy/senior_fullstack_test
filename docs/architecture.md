# Архитектура

Зависимости направлены к бизнес-правилам: HTTP и хранилище используют прикладной слой, прикладной слой использует домен. `Domain` и `Application` не зависят от Symfony, Doctrine или формата HTTP-ответов. Это правило проверяет `tests/Architecture/DependencyTest.php`.

## Backend

- `src/Domain/Order` — заказ, статусы, расчёт сумм и доставки. `OrderData` вычисляет суммы из позиций, проверяет переполнение и определяет необходимость проверки. `MarketplaceOrder` разрешает менять только статус и защищает финальные статусы.
- `src/Application/Order` — сценарии импорта одного заказа, импорта пачки и получения списка. Контракты внешних зависимостей находятся в `Port`, результаты — в `Result`.
- `src/Infrastructure/Marketplace` — разбор формата маркетплейса, Symfony Validator, нормализация телефона и денежных значений.
- `src/Repository` — адаптер хранилища на Doctrine ORM: чтение с блокировкой, сохранение заказов и выборка страницы. Решения о результате импорта принимаются прикладным слоем.
- `src/Infrastructure/Doctrine` — транзакции, повторные попытки при конфликтах и преобразование исключений Doctrine. XML-маппинг расположен здесь, чтобы бизнес-модель не зависела от ORM. Он соответствует существующей таблице `marketplace_order`.
- `src/Controller/Api` — HTTP-запросы, валидация параметров и преобразование результатов в прежний формат JSON. Даты и рубли для ответа форматирует `OrderResponse`.

Каждый заказ импортируется в отдельной транзакции. Уникальность обеспечивают индекс `(shop_id, marketplace_id)`, блокировка актуальной записи и повтор транзакции при конфликте. Callback транзакции может выполняться повторно; в нём нельзя отправлять сообщения или вызывать внешние сервисы.

## Frontend

Модуль находится в `frontend/src/app/orders`:

- `domain` — типы заказов и результатов импорта;
- `application` — состояние страницы и контракт `OrdersGateway`; сигналы доступны компонентам только для чтения;
- `infrastructure` — HTTP-адаптер и преобразование ошибок API;
- `presentation` — таблица, отчёт об импорте, форматирование дат и сумм, стили компонентов.

Корневой `App` собирает страницу и читает магазин из URL. Бизнес-расчёты выполняет backend; интерфейс отображает полученные суммы.

## Проверки

```sh
docker compose exec -T php php vendor/bin/phpunit
docker compose exec -T php php bin/console lint:container
docker compose exec -T php php bin/console doctrine:schema:validate
docker run --rm -v "$PWD/frontend:/app" -w /app node:24-bookworm-slim npm test -- --watch=false
```

Тесты домена и прикладных сценариев работают без запуска Symfony и базы. HTTP- и интеграционные тесты проверяют валидацию, изоляцию магазинов, повторный и параллельный импорт, восстановление после ошибок сохранения. Angular-тесты проверяют запросы, состояние и действия пользователя.
